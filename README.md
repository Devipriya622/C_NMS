# Enterprise Telecom Network Management System (NMS)

A modular, menu-driven C application for managing telecom network devices, viewing stored device metrics, detecting basic faults, managing alarms, recording events, and saving/loading data with CSV files.

> **Current implementation:** This is a local C command-line project. Metrics are stored in the application's `Device` structures; the project does not currently connect to real Cisco devices or collect live SNMP data. A graphical UI is deferred.

## Features

- Device inventory: add, list, search, update and delete using the Device Manager API.
- Monitoring: display a device's stored status and metrics.
- Fault detection: check device status and metrics against configured thresholds.
- Alarm management: create, list, acknowledge and clear alarms.
- Event logging: record and list events in memory.
- Persistence: save and load devices and alarms with CSV files.
- Separate test programs for individual modules.

## What each module does

| File | Responsibility |
|---|---|
| `include/nms_types.h` | Shared constants, status/severity/state enums and structures |
| `include/device_manager.h` | Public Device Manager API |
| `src/device_manager.c` | Keeps devices in a fixed-size array; implements add, list, search, update and delete |
| `include/monitoring.h` | Monitoring API declarations |
| `src/monitoring.c` | Looks up a device and displays its stored metrics |
| `include/fault_detection.h` | Fault detection API declarations |
| `src/fault_detection.c` | Checks for non-UP status, CPU > 80%, memory > 85%, packet loss > 2%, or response time > 200 ms |
| `include/alarm_manager.h` | Alarm API, including indexed access and restore helpers |
| `src/alarm_manager.c` | Keeps alarms in memory and implements alarm creation, acknowledgement, clearing and listing |
| `include/event_logger.h` | Event logging API declarations |
| `src/event_logger.c` | Stores event messages and timestamps in memory |
| `include/storage.h` | Save/load declarations for device and alarm records |
| `src/storage.c` | Reads and writes `devices.csv` and `alarms.csv` |
| `src/main.c` | Intended program entry point |
| `src/menu.c` | Intended interactive menu |
| `tests/*.c` | Standalone tests for each module |

## Data files

- `devices.csv` is created/overwritten by `save_devices()`.
- `alarms.csv` is created/overwritten by `save_alarms()`.
- Files are saved in the program's **current working directory**—normally the project root if you run the commands above.
- The `data/` folder exists, but the current storage implementation writes CSV files to the root folder instead.
- Current CSV format is simple comma-separated text; commas inside text fields are not supported.
- Load devices before loading alarms when starting up if alarm loading depends on referenced devices.
- Avoid loading the same CSV into already populated arrays; duplicate IDs may be rejected.

## Current limitations

1. **No live Cisco integration:** no SNMP polling or actual router/switch connection exists yet.
2. **Stored/simulated metrics:** monitoring displays values already present in each `Device`.
3. **In-memory event log:** events are not currently persisted to a file.
4. **Fixed capacities:** the structures use limits such as `MAX_DEVICES`, `MAX_ALARMS`, and `MAX_EVENTS`.
5. **CSV limitations:** fields containing commas are not supported by the current storage format.
6. **UI deferred:** this README covers the current C command-line project only.

## Troubleshooting

### `gcc` is not recognized

Install/configure MinGW-w64 and add its `bin` directory to Windows `PATH`. Reopen PowerShell and run `gcc --version`.

### Source file not found

Make sure you are in the project root:

```powershell
cd "C:\Users\Devi Priya\OneDrive\Desktop\C_NMS"
```

### Undefined reference / linker error

Include all modules needed by the test. For example, monitoring and fault detection need `src/device_manager.c` in the compile command.

### Duplicate device or alarm ID

The in-memory managers reject duplicate IDs. Use a fresh program process or reset the in-memory data before reloading the same CSV.
